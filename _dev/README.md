# _dev — 公開前の点検

チャットウィンドウメーカーを公開する（`main` に入れる）前に回す、自動の点検です。ツール本体ではありません。

- `_` で始まるフォルダは GitHub Pages（Jekyll）が公開しないので、このフォルダはサイトに出ません。
  **`.nojekyll` は置かないでください**（置くと `_dev/` も公開されます）。
- 点検はツールのファイル（`index.html` と `*.v*.js`）を読むだけで、書き換えません。

## 回し方

リポジトリのいちばん上で:

```bash
node _dev/check.js
```

全部が通れば `結果: すべて OK` と出て、終了コードは 0 です。どれかが NG なら終了コードは 1 です。
かかる時間は 20 秒くらいです（ブラウザ無しなら 4 秒くらい）。

### ブラウザを使う検査（4・5）の準備

4・5 は Chromium を Playwright で動かします。Claude Code のクラウド環境には最初から入っているので、そのまま回せます。
手元の PC で回すときは、最初に 1 回だけ:

```bash
cd _dev
```

```bash
npm install
```

```bash
npx playwright install chromium
```

Chromium を入れなくても、PC に Google Chrome か Microsoft Edge があればそれを使います。
どれも無いときは 4・5 を飛ばし、`[4] 飛ばした` と理由を出して、最後に「ブラウザが無いので確かめていません」と書きます
（このとき終了コードは 0。飛ばすのも失敗にしたいときは `--require-browser`）。

Node は 18 以上で動きます。ブラウザを使う検査は Node 20 以上（Playwright 1.63 の条件）です。

## 6 つの検査

| | 名前 | 確かめること |
|---|---|---|
| 1 | CSS を作る | `index.html` の `<script>` の順に `i18n` → `lang.en` → `lang.ko` → `presets` → `model` → `css` を Node の `vm` で読み込み、ひな形 9 つと、設定を乱数で変えた 100 通りの CSS を、日本語・英語・韓国語で作る。作る途中で例外が出ないこと |
| 2 | 文字列 | CSS に `undefined`・`NaN`・`[object Object]`・置き換え忘れの `{label}` などが無いこと。書き出す CSS のコメントの英訳・韓国語訳が抜けていないこと、訳文の `{wait}` などが元の文と同じこと |
| 3 | 文字欄からの注入 | 文字を入れられる欄（見出しの文字・フォント名・参加者アイコンの前に付ける文字・ルームの URL）に `*/ body{display:none} /*` や `"; } body{…}` などを入れても、CSS の文字列（`"…"`）やコメントの中に収まり、規則が増えないこと |
| 4 | 構文 | 作った CSS をブラウザの `new CSSStyleSheet()` の `replaceSync` に読ませ、書いた規則・宣言の数と、ブラウザが読んだ数が同じこと（無効なセレクタや値で捨てられていないこと） |
| 5 | 画面 | `index.html` を `?lang=ja`・`en`・`ko` × 幅 1280・375 で開き、コンソールのエラーが 0、横のはみ出しが 0（どのタブでも、折りたたみを開いても、設定しだいで出る行を全部出しても）、`I18n.missing`（訳の抜け）が空であること |
| 6 | 前回との差 | ひな形ごとの日本語の CSS が `_dev/snapshots/` に保存したものと 1 バイトも違わないこと |

## NG が出たとき

NG の下に、何が起きたかと、同じ原因の CSS が何本あったか、例（`ja:random:17` のような ID と行）が出ます。
同じ原因は 1 行にまとめるので、まず上から順に見てください。

- **ID の CSS を見たい**: `node _dev/check.js --dump=ja:random:17` で、その設定（JSON）と CSS を出します。
  ID は `ja:default`（開いた直後）、`ja:design:dicebox`（ひな形）、`en:random:17`（乱数の設定）、`ja:inject:…`（注入の検査）。
- **[6] で差が出た**: CSS の行の差（`-` が保存してあるもの、`+` が今の出力）が出ます。
  - 意図した変更なら `node _dev/check.js --update` で `_dev/snapshots/` を書き直し、ツールの変更と一緒にコミットします。
    PR の差分で「書き出す CSS がどう変わったか」をそのまま見られます。
  - 意図していない変更なら、それが不具合です。
  - 1〜4 のどれかが NG のときは、`--update` しても書き直しません（壊れた CSS を正解として残さないため）。
  - ひな形を足したときも `--update` で増やします。
- **[5] で横にはみ出した**: はみ出しの原因になっている要素（その要素を消すと、はみ出しが無くなるもの）を出します。

## オプション

```text
--update            _dev/snapshots/ を今の出力で書き直す（CSS を意図して変えたとき）
--no-browser        ブラウザを使う 4・5 を飛ばす
--require-browser   ブラウザが無いとき、飛ばさずに失敗にする
--seed=N            乱数の設定のシード（既定 20260924）
--cases=N           乱数の設定の数（既定 100）
--root=DIR          ツールのフォルダ（既定: _dev の一つ上）。壊した一時コピーを調べるとき用
--dump=ID           ID の設定と CSS を出して終わる
--help              一覧を出す
```

`npm run check` / `npm run update`（`_dev` の中で）でも回せます。

## 仕組みのメモ

- **Node で CSS を作る**: 空の `window` と、`i18n.v1.js` が使うだけの `document` を用意して、ツールのスクリプトを `vm` で動かします。
  ブラウザで開いた直後の CSS と、Node で作った既定の状態の CSS が同じことも 5 で確かめます（同じでなければ、読み込むスクリプトが足りません）。
- **乱数の設定**: `index.html` の `data-bind` の欄（スライダーの最小・最大・刻み、選択肢、チェック、色、文字）から値を選びます。
  欄ごとに乱数の列を分けているので、欄を足しても、ほかの欄の値は変わりません。シードが同じなら毎回同じ設定です。
- **CSS の読み方**: コメントや文字列を正規表現で消すと `content: "…/*…"` で誤るので、CSS の仕様どおりに字句を区切る小さな読み取りを入れています（文字列・エスケープ・コメント・`url()`・括弧）。
  ただし最後の判定（4）は、必ずブラウザに読ませた結果です。
- **規則と宣言の数え方（4）**: `replaceSync` は `@import` を受け付けないので、先に取り除いてから読ませます（`@import` が規則より後ろにあると読み込まれないので、その並びは別に確かめます）。
  宣言は 1 つずつ別のシートに読ませて、捨てられていないかを見ます。ブラウザは `margin` などの一括指定を個別のプロパティに分けて数えるので、シート全体の数では比べられないためです。
- **注入（3）**: 欄に `Zq9Mark` だけを入れた CSS と、`Zq9Mark` に続けて壊しにかかる文字を入れた CSS を作り、文字列とコメントの外側の字句が同じことを確かめます。ブラウザが読む規則・宣言の数も比べます。
  その欄が CSS に出てくる設定は `check.js` の `CONFIG.textFields` に書いてあり、`index.html` に文字欄が増えたのにここに無いと NG になります。
- **画面（5）**: その場で小さな Web サーバーを立てて開きます。Google Fonts などほかのサイトへの読み込みは空の応答を返すので、ネットにつながらなくても同じ結果になります。
- **スナップショットの改行**: `_dev/.gitattributes` で `snapshots/*.css` の改行を変えないようにしています（Windows の Git が CRLF にすると、1 バイト違いになるため）。

## ほかのツールに写すとき

`check.js` の先頭の `CONFIG` だけを書き換えます（ほかの部分はツールに依存しません）。

- `name`: 出力の見出しに出すツールの名前
- `nodeScripts`: Node で読むスクリプト（`.vN.js` を除いた名前）。DOM を触らずに CSS を作れるものだけ。順は `index.html` のとおり
- `designs` / `defaultState` / `designState` / `normalize` / `build` / `options`: そのツールの `window.Xxx` の名前と、CSS を作る関数の呼び方
- `ignoreControls`: CSS に関係しない `data-bind` の欄
- `couple`: 欄を変えたときに UI がほかの欄も変える決まり（無ければ何もしない関数に）
- `textFields`: 文字欄ごとの「CSS に出てくる設定」
- `page`: タブのボタン、条件つきの行、開いた直後の CSS の場所、訳の抜けを探すために押すボタン（`exercise`）

そのうえで `node _dev/check.js --update` でスナップショットを作り、`.gitignore` に `_dev/node_modules/` を足します。
